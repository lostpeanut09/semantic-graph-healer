## 2024-05-28 - [Accessible Tabs and Buttons]
**Learning:** Screen reader users navigating by tab hear "Execute, Button" repeatedly when iterating through list items without sufficient contextual labels. Relying solely on `disabled` attributes on buttons or opacity classes doesn't explain *why* an action is disabled, and mouse users might not realize a button is unclickable without standard styling like `cursor: not-allowed;`. Wait states for async operations need `aria-busy` to communicate progress correctly.
**Action:** When creating repeating components with action buttons (like suggestion cards), add context to ARIA labels (e.g. `aria-label="Execute fix for {suggestion.link}"`). Always apply `title` tooltips and inline `cursor: not-allowed` alongside `disabled` states to offer clear feedback for both mouse and screen reader users. Use ARIA tablist roles (`role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`) when using tab-based UI navigation.
