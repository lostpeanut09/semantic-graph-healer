  <action>
    - **Step 1 – `no-unused-vars`:** For each flagged variable, either remove it if truly unused, or prefix with `_` to explicitly silence the rule for intentionally-unused parameters (e.g., event listeners where typed signature must match an interface).
    - **Step 2 – `require-await`:** For each async function where the body contains no `await`, remove `async` unless the function's signature requires it (e.g., an `onChange` callback typed as `async`).     - **Step 3 – `no-floating-promises`:** For each dangling `void someAsyncCall()`, either convert to `await someAsyncCall()` (if the enclosing scope is async) or add an explicit inline `.catch(err => console.error(err))` wrapper. If the intent is intentional fire-and-forget (managed elsewhere), prefix with a documented `void` plus optional `/* eslint-disable-next-line @typescript-eslint/no-floating-promises */`.

The existing ESLint rule override already allows `warn`/`error`/`debug`/`info` globally, but the inline comment makes intent explicit for reviewers; this also satisfies STRIDE T-13-02-01.
